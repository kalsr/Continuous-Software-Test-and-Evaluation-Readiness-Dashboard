Software-Readiness-Testing-Dashboard

What the Application Does

The Continuous Software Test and Evaluation Readiness Dashboard, developed by Randy Singh from Kalsnet (KNet) Consulting Group, addresses a core problem in defense & Other software industry today: new releases can be built and fielded much faster than they can be objectively assessed. The dashboard collects the evidence that an automated software pipeline already produces and turns it into a clear, consistent readiness decision for every release. Each release candidate receives one of three outcomes: approve, conditional approval, or not ready. Every outcome comes with the evidence and reasoning behind it, so reviewers can approve good releases quickly and focus their time on the ones that need attention.

How It Works

The application scores each release across four evidence pillars, each rated from zero to one hundred. Test quality combines the test pass rate, code coverage and the share of requirements linked to passing tests, and reduces the score for tests that were skipped. Security starts from vulnerability findings weighted by severity, so critical findings cost the most points, then adds credit for security hardening compliance and subtracts points when a software bill of materials is missing or the build is not signed. Performance compares measured response time under load with the required response time. Stability uses the share of recent deployments that caused failures and the size of the code change. The four pillars are combined with weights into one readiness score. That score is checked against a required bar that rises with mission criticality, and the remaining risk is scaled by how critical the system is and how many mission threads it supports. Release gates then act as firm stop points, for example an open critical vulnerability on a high criticality system or an unsigned build headed for operational use. When historical data shows whether fielded releases later caused incidents, the dashboard also checks how well its decisions predicted those incidents.

Data and Evidence Handling

The dashboard works with synthetic data for training, demonstrations and testing, or with real release records uploaded as CSV files. It reads standard pipeline outputs directly, including JUnit XML test reports, SARIF security scan reports and scanner CSV files, and uses them to fill in the release evaluation form automatically. Results can be exported as CSV, plain text, Word or PDF, and existing result files in any of those formats can be uploaded and viewed inside the application.

Tools Used

The application is written in Python, with Streamlit providing the interactive web interface. Pandas and NumPy handle data processing and the synthetic data generator, and Altair draws the charts, heatmaps and trend lines. Graphviz renders the flowcharts in the guide. The Python XML and JSON libraries parse test and security scan reports, while python-docx, pypdf and fpdf2 create and read Word and PDF files.

Real-World Benefits

The dashboard shortens approval time by replacing weeks of manual evidence gathering with an automated, repeatable assessment that runs with every build. It gives decision makers a defensible audit trail, because every score, gate and formula is visible and explained. Every release is held to the same standard, which reduces subjective judgment and inconsistency between reviewers. Raising the bar for mission critical systems matches the depth of review to operational risk. Security and supply chain risks are surfaced early through vulnerability, software bill of materials and signing checks. Program managers get a portfolio view showing which systems are improving or slipping. Over time, comparing decisions with real field outcomes lets the organization tune the weights and thresholds so its assessment process keeps getting better. The result is that warfighters receive capability faster while confidence in what is being fielded stays high.
